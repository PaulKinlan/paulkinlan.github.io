Coding Agent System Prompts:
A Comparative Deep Dive

Evaluating prompt design, instruction density, and context overhead across Claude Code, DeepSeek Coder, OpenAI Codex, OpenCode, T3 Code, and the Fleet Multi-Agent Harness.

Comparative Matrix Architectural Fixes Extracted Prompts

Executive Summary

As language models scale in raw coding capability, the system prompt is no longer just a set of instructions; it is the operating system ABI (Application Binary Interface) that governs how models manipulate the host filesystem, handle fatal errors, manage context windows, and interact with other autonomous processes.

In this audit, we examine the production system prompts and control architectures of five premier coding agent implementations, benchmark them against the Exe.dev Fleet prompt architecture (roles/common.md, roles/coord.md, and role specifications), and identify four concrete improvements that reduce token bloat while boosting reasoning accuracy.

Anatomy of the Prompts

1. Claude Code: The Dynamic Harness Mindset

Claude Code treats the model not as a generic conversationalist, but as an interactive CLI tool operating with user-selected permissions. Key prompt excerpts demonstrate how it enforces safety and clickability:

You are Claude Code, Anthropic's official CLI for Claude. You are an interactive agent that helps users with software engineering tasks. Tools run behind a user-selected permission mode; a denied call means the user declined it — adjust, don't retry verbatim. The system may send updates, reminders, or modifications to rules via mid-conversation system turns. Prefer the dedicated file/search tools over shell commands when one fits. Independent tool calls can run in parallel in one response. Reference code as file_path:line_number — it's clickable. Write code that reads like the surrounding code: match its comment density, naming, and idiom.

Key Architectural Takeaway: Rather than dumping 50 edge-case rules into the boot prompt, Claude Code injects <system-reminder> blocks on specific turns (e.g., when Plan mode is activated or a test failure occurs).

2. OpenAI Codex CLI: The AGENTS.md Hierarchy

OpenAI Codex's system prompt is remarkably brief (less than 500 words), delegating project-specific behavior entirely to the filesystem:

You are a coding agent running in the Codex CLI, a terminal-based coding assistant. You are expected to be precise, safe, and helpful. ## AGENTS.md Spec: - Repositories often contain AGENTS.md files specifying coding conventions, organization patterns, or test execution steps. - The scope of an AGENTS.md file covers the directory tree rooted at its folder. - You must strictly obey instructions in any AGENTS.md file whose scope includes a file you modify.

3. The Exe.dev Fleet Architecture: Ledger & Cross-Family Verification

The Fleet prompt architecture solves an existential problem that neither Claude Code nor Codex addresses: autonomous multi-agent coordination without human stalling.

## Rules that never bend 1. Beads is the ledger. Every piece of work has a bead. Claim it with bd update <id> --claim. 2. Never review your own work. A different model family reviews every change. 3. Verify for real. "It serves" or "tests pass" is not "it works". Drive the actual behaviour in a browser. 4. Long commands: fleet-gate, then stop. Never poll with sleep loops or repeated status checks.

Proposed Architectural Improvements for Fleet Prompts

1. Compact roles/common.md by 40%

Problem: roles/common.md has grown to 15,580 bytes (~3,800 tokens), close to the 16KB deployment limit. Over 40% of its content describes mechanisms enforced deterministically by daemons (e.g. 6/h wake limits, reaper thresholds, process groups).
Fix: Strip daemon implementation details from the prompt. Replace verbose explanations with terse, actionable invariants.

2. Adopt Clickable Terminal Links (file:line)

Inspiration: Claude Code's clickability rule.
Fix: Add an explicit formatting rule: "Always reference code locations as path/to/file.ext:line." When reviewers report findings on beads or terminal logs, operators can click directly into the exact line in VS Code or iTerm.

3. Hypothesis-First Bounded Turn Rule

Inspiration: SWE-agent's DISCUSSION → COMMAND pattern.
Fix: DeepSeek and GLM implementers sometimes execute 8-10 speculative bash tool calls without writing code or committing. Enforce: "State 1 concrete hypothesis → run focused probe → commit code → end turn."

4. Dynamic Phase Injection vs Static Bloat

Inspiration: Claude Code's <system-reminder>.
Fix: Instead of having all reviewer and landing rules in every lane's system prompt, have lanes.sh spawn inject role criteria only when that specific phase begins.
